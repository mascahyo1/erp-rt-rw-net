### 5. **🚨 FATAL Security Fix** — Company Selection Bypass di 3 Login Pages
**File diubah:** 5 file backend (3 controller + 1 route + 1 component) + 4 file frontend (3 login view + 1 shared component) = **9 file total**

- ✅ **Root cause** (3 layer):
  1. **UI tidak kirim company_id**: LoginPerusahaan/Karyawan/Pelanggan punya `<CompanySearchInput v-model=selectedCompany>` tapi `useForm()` tidak include `selectedCompany.value.id`. Variable dibuat tapi TIDAK PERNAH dikirim ke backend.
  2. **Backend tidak validasi company_id**: 3 controller (AdminCompany, Employee, Customer) hanya validasi `email+password`. Field `company_id` required gak ada.
  3. **CompanySearchInput pakai hardcoded FAKE data**: 50 perusahaan hardcoded dengan `id: 1,2,3` (integer) tapi DB `companies.id` pakai UUID v7. Dropdown menampilkan perusahaan yang GAK ADA di DB.

- ✅ **Exploit (sebelum fix)**: POST /login-perusahaan dengan `email=admin@netsejahtera.com + password=password123` (gak perlu company_id) → **302 redirect ke dashboard**. Cross-tenant attack: user dari company A bisa login ke company B manapun.

- ✅ **Fix**:
  - **3 Login Views**: tambah `company_id` ke form via `transform()` callback + `*` required indicator + error display
  - **LoginPelanggan bonus fix**: register form `selectedCompany.value?.value` → `?.id` (value tidak exist, harusnya id)
  - **3 Auth Controllers**: tambah `company_id` => `['required', 'string', 'exists:companies,id']` + check `user.company_id === company_id` setelah `attempt()` (kalau mismatch → `Auth::guard()->logout()` + throw 'Email tidak terdaftar di perusahaan ini.')
  - **CompanySearchInput.vue**: ganti 50 hardcoded fake companies dengan `fetch()` ke real API + support pagination/search/loading/error state + data-testid untuk testability
  - **API baru `GET /api/companies/search?q=&page=`** di landing-page.php: public endpoint (no auth) query companies aktif dengan filter by name/email/address, return JSON `{data, hasMore, page, total}`

- ✅ **Test verification** (Playwright FixTest.cjs, **9/10 PASS**):
  - T1: Login Perusahaan tanpa company → **BLOCKED** ✓
  - T2: Login dengan company SALAH (cross-tenant attack) → BLOCKED dengan error 'Email tidak terdaftar di perusahaan ini.' ✓
  - T3: Login dengan company BENAR (admin's own UUID) → **DASHBOARD terbuka** ✓
  - T4: Login Karyawan tanpa company → BLOCKED ✓
  - T5: Login Pelanggan tanpa company → BLOCKED ✓
  - T6: Login SaaS (no company field) → TIDAK ADA REGRESSION ✓

**Impact**: Security vulnerability closed. Sebelum fix, siapa saja dengan email+password valid bisa login ke company manapun. Sekarang harus pilih company yang sesuai — kalau tidak, di-block di backend. Login SaaS single-tenant TIDAK berubah (no company field by design).

## Catatan Tambahan

**Lesson learned (konsolidasi):**
1. **Test methodology** — `fill()` set value via JS, `type()` simulate real keystrokes. Untuk search/dropdown component, WAJIB test dengan `type()` (atau manual test) supaya keydown event bugs ke-detect.
2. **Audit existing tests** — saat refactor, cek selector stability. Selector `'.fixed.z-\\[60\\]'` fragile ke Tailwind class change. Selector `data-testid` stable lintas refactor.
3. **Per-key preventDefault** — saat handler ke-trigger untuk banyak keys, JANGAN panggil `preventDefault()` blanket. Scope per-key.
